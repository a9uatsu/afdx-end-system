# 128 发送 VL / 4096 接收 VL 重构方案

**前提**：当前基线 15 个用例全绿；顶层已参数化到 32/64 中间档。
**目标**：128 发送 VL、4096 接收 VL，保持 100 Mbps 与 <1–2 ms 时延。
**原则**：每一步都以全绿回归收尾，任何一步都可单独回退。

---

## 1. 现状瓶颈

| 侧 | 现有实现 | 4096/128 规模下的问题 |
|---|---|---|
| 发送 VL 表 | 寄存器堆 + 组合读多路器 | 252 bit × 128 选 1，约 10.8k LUT 仅用于读 |
| 发送调度 | 每 VL 一个 32 bit 递减器 + 全并行扫描 | 128 个递减器 4k+ 寄存器；扫描链深 |
| 接收 VL 查找 | 4096 路并行比较 + 优先级编码 | 寄存器状态 176 kbit，超过 136k LUT |
| 接收状态写 | 变量索引写 `ic_win[m_idx]` | 65k 寄存器 + 大规模选择逻辑 |

**结论**：不是优化问题，是"状态必须进内嵌存储"的硬约束。

---

## 2. 目标架构

### 2.1 发送侧

```
配置写口 ──► TX VL 表 RAM（128 × 252 bit，4 块 9kbit）
                     │ 单口读（一次一条记录）
                     ▼
 全局时基(32bit) ──► 后台扫描器（4 VL/拍，32 拍一轮）
                     │ 比较 next_start ≤ now
                     ▼
                 就绪 FIFO（16 深，7 bit/项）
                     │
                     ▼
              轮询仲裁 ──► 帧组装器（读同一 RAM 取参数）
```

- `next_start` 存 RAM（128 × 32 bit，1 块）；
- 帧开始发送时写回 `next_start = now + BAG`；
- 扫描 4 个 VL/拍 → 32 拍一轮 = 640 ns，BAG 最小 1 ms，余量约 1500 倍；
- SN 并入 VL 记录（省一路读多路器）。

### 2.2 接收侧

```
帧解析出 VLID ──► 二分查找（12 拍）──► RX 状态 RAM（4096 × 48 bit，22 块）
                                          │ 读出：last_sn/ic_win/flags
                                          ▼
                                      冗余管理判定（纯组合，1 拍）
                                          │
                                          ▼
                                      写回同一记录（读-改-写）
```

- 表按 VLID 升序排列，上电由配置序列写入；
- 每帧 1 次查找（12 拍）+ 1 次读 + 1 次写 ≈ 15 次 RAM 访问；
- 100 Mbps 下 64 字节帧间隔 6.7 µs（335 拍），访问预算充足；
- `fault_vec[4095:0]` 宽端口取消，改为"按索引读状态"接口。

### 2.3 帧缓存

`afdx_frame_rx` 的 2048×8 缓存改为双 bank 同步读（4 块 9kbit），
解析器多遍扫描改为"带地址预取"的同步读；预计释放约 1000 LUT。

---

## 3. 资源预算

| 结构 | bit | ≈9kbit 块 |
|---|---|---|
| RX 状态表 4096×48 | 196,608 | 22 |
| TX 表 128×252（精简后 165） | 32,256 | 4 |
| TX next_start 128×32 | 4,096 | 1 |
| 帧缓存双 bank | 32,768 | 4 |
| **合计** | **265,728** | **31（5.8%）** |

逻辑预算：协议逻辑约 300 + 查找状态机 200 + 扫描器/FIFO 600 + 状态读口 300 ≈ **1.4k LUT**，
加布线余量按 **2.5–3k LUT** 评估。

---

## 4. 分步实施（每步结束跑全量回归）

| 阶段 | 改动 | 验收 | 回退点 |
|---|---|---|---|
| S1 | 帧缓存改双 bank 同步读 | 15 用例全绿；LUT 下降约 1000 | 保留原分支 |
| S2 | TX VL 表改 RAM + 扫描器 + 就绪 FIFO | 32 VL 压测：BAG 间隔 ≥ 配置值、无饿死 | 参数切回 4 VL |
| S3 | RX 状态表改 RAM + 二分查找 + 读改写 | 64 VL 压测全对；再扩到 4096 | 参数切回 8 VL |
| S4 | 接口改造（宽端口 → 状态读口）+ 128/4096 参数 | 全量回归 + 容量压测 | 保留 32/64 版本 |
| S5 | 综合/实现报告与资源复核 | WNS ≥ 0、存储 ≈ 266 kbit | — |

---

## 5. 测试计划

1. **TX 容量**：128 VL、BAG 1/2/4 ms 混合，10 万帧，统计每条 VL 的最小起始间隔与最大抖动；
2. **RX 容量**：4096 个 VLID 轮询，检查查找命中率、计数器闭合（接收 = 交付 + 重复 + 拒绝）；
3. **资源复核**：综合后 `Total memory bits` 应接近 266 kbit（接近说明进了 RAM；为 0 说明还在 LUT）；
4. **时序**：50 MHz 下 WNS ≥ 0，重点看 RAM 读→比较→写回。

---

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 二分查找需要排序表，配置写入复杂 | 上电配置序列按 VLID 升序写；运行期不支持乱序插入（文档化） |
| RAM 读延迟改变解析时序 | 每遍扫描加地址预取，状态机按"发地址→下一拍用数据"重写 |
| 4096 表写回与查找共用端口 | 查找期间禁止写；每帧串行完成查找→判定→写回 |
| 大改导致回归失败难定位 | 五个阶段独立提交，每阶段保留可回退参数 |
